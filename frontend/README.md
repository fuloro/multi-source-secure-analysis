# 前端应用与场景展示模块

负责人：成员 D。当前状态：规划阶段，尚无前端、模拟数据或演示材料。

## 模块目标

设计可解释的联合分析场景，提供模拟 CSV 和简洁交互界面，展示“配置分析 → 安全计算 → 结果展示 → 明文对照”的完整流程。

## 前期工作：与 C 共同设计架构

- 确定两家机构各自持有的字段、为什么需要 Join、最终需要展示哪些聚合统计。
- 明确数据拥有方、计算参与方、结果接收方及结果恢复规则。
- 与 C 确认参数、任务状态、错误提示和结果格式，使用显式模拟模式制作界面原型。
- 阅读论文并整理“论文步骤—算法模块—系统流程—展示内容”的对照说明，避免把尚未实现的能力写成成果。

## 候选应用场景

两家机构按用户 ID 做 inner join，统计共同用户的年龄段分布，并扩展为按年龄段汇总某个数值指标。

| 数据 | 示例字段 | 用途 |
| --- | --- | --- |
| 机构 A 合成表 | `user_id`, `age_band` | 提供连接键与分组字段 |
| 机构 B 合成表 | `user_id`, `amount` | 提供连接键与数值指标 |
| 最终结果 | `age_band`, `count`, `sum_amount`, `mean_amount` | 展示共同用户或匹配记录的统计 |

唯一键场景下可解释为共同用户计数。重复键场景中 `count(*)` 统计匹配记录，不能直接标为去重用户数。实际字段和语义待团队确认。

## 后期实现范围

1. 生成可复现的合成 CSV，记录随机种子、字段定义、规模、重叠比例和重复键设置。
2. 选择 Streamlit 或 Gradio，实现输入选择/上传、连接键、分组键和聚合指标配置。
3. 通过后端运行分析，展示运行状态、结果表、适合的图表以及一致性对照。

5. 整理论文对照说明、一页纸项目说明、演示步骤和演示材料。

集中上传双方 CSV 的单机界面只适合合成数据演示。多方部署应由各参与方本地加载数据，前端传递配置或数据引用；部署说明必须讲清实际数据路径。
