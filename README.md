# 多源数据安全协同分析方法研究与应用

基于秘密共享技术，实现多方数据的安全联合分析，并在具体应用场景中完成可运行的系统展示。

本项目计划研究并实现安全连接（Join）与分组聚合（Group-By），将两者串联为联合分析流水线，再通过前端展示配置、运行结果与一致性验证结果。

> 当前状态：已提交明文 Join、SPU Group-By 和合成数据联调；安全 Join 及完整安全流水线仍待实现。

## 技术方向

- 首先评估 SecretFlow / SPU，必要时对比 MP-SPDZ；最终选型以协议实现便利性、部署条件和前后端集成为依据。
- 前端候选为 Streamlit 或 Gradio，待部署方式和后端接口明确后决定。
- 明文参考计算与 MPC 计算必须明确区分；明文路径仅用于合成数据的开发验证与演示对照。
- 当前已测试 WSL Python 3.11、SPU 0.9.5、三方半诚实 ABY3。

## 预期数据流

```text
参与方 A 的本地表 ─┐
                  ├→ 输入校验与秘密共享 → 安全 Join → 安全 Group-By
参与方 B 的本地表 ─┘                                      ↓
                                               按约定向结果接收方恢复
                                                         ↓
                                               前端展示最终聚合结果

合成数据 → 明文 Join + Group-By → 与 MPC 最终结果对照
```

Join 到 Group-By 的中间结果应保持秘密共享状态。若实现需要公开长度、键集合或其他信息，必须在模块能力说明中列出，交由架构设计统一确认。

## 开发与协作约定

1. 各负责人在所属目录内开发，并持续更新该目录的 README；跨模块改动同步说明影响。
2. 先确定输入、输出、类型、错误和泄露边界，再整合。各模块文档列出的接口是讨论起点，最终约定由 C 与 A、B、D 共同确认。
3. 每个算法提交时附带可复现的最小示例、确切依赖版本、运行命令和能力限制；未实现的功能明确标注。
4. 建议使用 `feat/join-*`、`feat/groupby-*`、`feat/backend-*`、`feat/frontend-*` 分支，通过 Pull Request 合入 `main`；分支保护尚未配置。
5. 不提交真实个人数据、账号凭据、私钥或本地运行产物。演示数据应为可复现生成的合成数据。
