# 安全 Join 算法模块

负责人：成员 B。当前状态：已提交明文 inner join 与实验脚本，安全 Join 待实现。

环境可行性进展：2026 年 11 月 2 日已完成独立的 ABY3 小规模 Join 基线验证，覆盖唯一键、重复键、无交集及填充行，共 5 个用例通过。[验证记录与限制](../../docs/join-validation.md)包含复现命令。该示例位于后端验证目录，尚不代表本模块的正式算法与接口已交付。

## 模块目标

研究项目论文中的安全连接方法，优先评估在 SecretFlow / SPU 下实现的可行性。先跑通两方表的 inner join，再分别处理键唯一与键非唯一的情况。

## 负责范围

- 说明论文协议的主要步骤、秘密共享表示、威胁模型与信息泄露边界。
- 实现可独立运行的最小 Join 示例，并记录数据规模、依赖版本和运行方式。
- 明确重复键的输出语义：某个键在左右表分别出现 m、n 次时，标准 inner join 应产生 m×n 条匹配记录；若实现不支持，必须显式拒绝并说明。
- 将结果以可供 Group-By 使用的秘密共享表示传给后端，避免为串联模块而恢复明文中间表。
- 记录空交集、空表、缺失键、字段重名、类型不一致和输出容量不足等边界处理。

## 初步输入输出约定

| 项目 | 预期约定，待验证 |
| --- | --- |
| 输入 | 参与方各自提供的数据或共享对象、左右连接键、需要保留的字段、运行配置 |
| 输出 | 秘密共享的匹配记录、有效行掩码（若采用填充）、输出字段模式 |
| 类型 | 键编码、字符串支持、整数范围与定点数精度须与 C、A 统一 |
| 容量 | 重复键可能扩大结果；最大输出容量、填充方式与溢出行为必须明确 |
| 错误 | 不支持的类型、模式、超限配置应返回可理解的错误 |

具体函数签名由 A、B、C 联合确认。PSI 或仅返回共同 ID 的实现不能直接视为完整的重复键 Join，需要说明后续记录匹配步骤。

## 交付内容
