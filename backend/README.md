# 后端整体架构与整合模块

负责人：成员 C；成员 D 前期共同参与架构与应用需求设计。当前状态：已包含 Join、Group-By 和合成数据联调入口，安全 Join 与完整服务仍待实现。

## 模块目标

将安全 Join 与 Group-By 串联为可参数化的联合分析流程，管理参与方输入、协议运行、最终结果恢复和端到端验证，为前端提供统一调用入口。

## 前期可独立开展的工作

- 与 D 共同确定应用场景、参与方各自持有的字段、连接关系和最终统计指标。
- 调研 SecretFlow / SPU 与 MP-SPDZ 的运行环境、协议扩展方式和服务集成成本。
- 与 A、B 明确输入输出、共享类型、键编码、填充掩码、结果容量和错误语义。
- 定义安全模型、计算参与方、数据拥有方与结果接收方，说明它们是否为同一角色。
- 基于合成数据构建明文参考流程；可提供标明“模拟模式”的接口帮助 D 开发界面。

## 算法就绪后的整合工作

1. 校验配置和数据模式，在各参与方侧加载输入。
2. 初始化计算环境，完成所需的输入共享与编码。
3. 调用 Join，保持中间结果为共享状态。
4. 将 Join 输出和有效行掩码传入 Group-By。
5. 按授权约定恢复最终聚合结果，整理指标与运行状态。
6. 在合成数据上执行明文参考流程并比较结果，输出验证记录。

## 初步配置与前端接口

| 配置 | 说明 |
| --- | --- |
| 参与方与输入 | 参与方标识、各自输入路径或已登记数据引用；区分单机模拟和多方部署 |
| Join | 左右连接键、连接类型、保留字段、输出容量 |
| Group-By | 分组字段、聚合源字段、操作和输出名 |
| 执行 | MPC 运行环境、协议参数、数据规模限制 |
| 结果 | 接收方、输出位置、是否启用合成数据对照、误差阈值 |

建议对前端提供“校验配置、提交运行、查询状态、读取结果”四类操作；函数调用或 HTTP 服务形式待选型后确定。目前没有已实现的 API。

结果建议包含运行标识、状态、最终聚合表、耗时、验证结论和可理解的错误。日志不记录原始数据、秘密份额或明文中间表。

## 验证与交付

- 明文与 MPC 使用相同 Join 语义、编码、缺失值规则和有效行规则。
- 先按分组键对齐再比较，不能依赖输出行顺序；计数精确比较，定点数按约定绝对/相对误差比较。
- 覆盖唯一键、重复键、无交集、空输入以及 count/sum/mean 组合。
- 交付架构设计说明、可参数化应用脚本、前端调用说明和端到端验证记录，记录版本、配置及可复现数据。

`join/` 保存连接成果；`groupby/` 保存聚合代码、依赖和测试；`integration/` 保存联调入口与说明。
