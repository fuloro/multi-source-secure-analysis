# 四周实施计划与提交安排

项目：多源数据安全协同分析方法研究与应用。

计划周期：**2026 年 10 月 30 日—11 月 26 日，共 28 天**。以任务 1 完成后的次日作为起点；以下日期和时间均为北京时间。此文档为执行计划，不代表功能已经完成。

## 一、一个月结束时需要交付什么

实现一个可复现的合成数据演示：两家机构各自持有一张表，按 ID 进行安全 inner join，再按指定字段完成 count、sum、mean 分组聚合，按约定恢复最终结果，并在界面上展示与明文参考计算的对照。

| 成员 | 主要责任 | 最终交付 |
| --- | --- | --- |
| A | Group-By | 算法模块、独立示例、验证记录、能力与泄露边界说明 |
| B | Join | 唯一键/重复键 inner join 实现与验证、独立示例、能力与泄露边界说明 |
| C | 架构与整合 | 架构说明、参数化应用脚本、前端调用入口、端到端验证记录 |
| D | 前期架构协作、场景与前端 | 论文对照说明、合成 CSV 与生成方式、前端、一页纸说明、演示材料 |

D 牵头汇总答辩帮助手册，A、B、C 分别提供本模块的原理、结果和常见问答。本计划只安排手册制作时间，不包含手册正文。

默认目标是两家数据拥有方的小规模演示。实际计算参与方数量、安全模型、协议、运行环境与数据规模在第一周用实测确定，不能将“两家机构”直接等同于“两方计算协议”。

依赖主线：**共享格式与接口确认 → A/B 可整合算法 → C 真实流水线 → D 真实界面展示 → 全员验收**。

- 与 B、C 在同一套运行环境中验证最小秘密共享计算，记录系统、Python/库版本、启动命令和恢复结果。
- 用极小的固定数据尝试分组计数与求和，确认排序/分段/掩码等所需操作的实现路径；定位 mean 的除法与精度问题。
- 提出分组键编码、空值规则、有效行掩码和输出表示，向 B、C 说明限制。

**11/05 20:00 前提交：**论文阅读记录、环境运行记录、算法设计草案、接口与能力清单初稿；可运行的小实验或阻塞点的复现步骤。

### 成员 B：Join

- 阅读安全连接相关论文，区分 PSI、记录匹配与完整 Join 的功能，明确论文方法如何映射到实现。
- 在共同环境中验证唯一键 inner join 的关键操作，分析重复键 m×n 匹配所需容量及代价。
- 尽早验证秘密共享输出能否直接传给 Group-By，列出是否公开长度、键或匹配关系。
- 提出键类型、字段重名处理、输出填充与容量超限策略。

**11/05 20:00 前提交：**论文阅读记录、Join 设计草案、唯一键关键路径实验、重复键可行性结论、接口与限制初稿。

### 成员 C：架构与整合

- 牵头选择运行环境和 MPC 库；与 A/B 用相同小实验评估 SecretFlow/SPU，必要时比较 MP-SPDZ，记录选型理由和复现步骤。
- 与 D 画出数据归属、输入共享、Join、Group-By、最终恢复、明文对照的流程；明确数据拥有方、计算参与方和结果接收方。
- 组织 A/B/D 统一共享类型、键编码、有效性掩码、聚合语义、配置格式与错误格式。
- 定义参数化应用脚本和前端调用入口草案；制定小规模验证样例。

**11/05 20:00 前提交：**架构设计 v0.1、环境与选型记录、跨模块接口 v0.1、配置样例及验证方案。

### 成员 D：架构协作与场景设计

- 与 C 共同阅读论文与设计架构，重点解释各方持有什么、计算过程公开什么、最终展示什么。
- 确定一个主场景及字段字典，例如 A 持有 `user_id, age_band`，B 持有 `user_id, amount`。
- 设计合成数据的重叠比例、重复键和边界样例；列出预期结果，区分“匹配记录数”和“去重用户数”。

**11/05 20:00 前提交：**场景说明、字段字典、数据分区图、界面草图、论文对照说明提纲；共同审阅架构 v0.1。

**本周验收：**全员同意环境与接口；至少跑通 MPC 基础实验，并对 Join/Group-By 的关键实现路径给出证据或明确阻塞。若关键路径未通过，11/05 必须安排修复与重排，不能默认第二周能交付。

## 八、时间不足时的处理原则

| 风险 | 最晚检查时间 | 处理方式 |
| --- | --- | --- |
| 环境或 MPC 库关键操作无法跑通 | 11/02 发现，11/05 决策 | C 牵头集中解决；必要时切换运行环境或库，并同步重排受影响任务 |
| 重复键 Join 代价过高或未实现 | 11/05 评估，11/12 交付核验 | 保留小规模正确实现目标；先贯通唯一键主链路，重复键继续修复并记录限制，不能宣称已完成 |
| A/B 的共享格式无法串联 | 11/09 前检查 | 由 C 统一适配与契约，避免分别恢复中间明文后重新输入 |
| 界面等待真实后端 | 第 1—2 周 | D 先使用显式模拟接口；第三周必须切换真实后端验收 |
| 数据规模导致运行过慢 | 第 3 周 | 选择实测可运行的较小演示规模，报告真实耗时；不预设性能结论 |
| 最后一周仍有集成缺陷 | 11/23 冻结检查 | 优先修复主链路，停止新增图表、多表、更多 Join 类型等扩展 |

核心目标为安全 inner join、count/sum/mean、真实流水线、明文一致性和基本界面。多表连接、其他 Join 类型、多列分组、高并发、复杂权限与大规模性能优化作为扩展项。重复键属于原定交付目标，若最终无法完成，应在验收中明确标为未完成，不自动降为可选功能。

前期优化重点放在统一环境与编码、尽早验证共享数据衔接、减少不必要的中间恢复和建立可复现基准；算法语义正确后再进行性能优化。
