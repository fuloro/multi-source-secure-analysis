## 算子接口提案

以下是逻辑接口，不是秘密份额序列化的传输格式。

```text
groupby(shared_table, public_spec) -> shared_grouped_table

shared_table:
  keys[N, K]          秘密的整数编码分组键
  values[N, V]        秘密的有界整数度量值
  valid[N]           秘密有效位：1 表示真实行，0 表示填充行或未匹配行

public_spec:
  数据模式及版本、N、K、V、选用的键列和数值列、聚合操作列表
  整数位宽、数值界限、算法版本、运行时标识

shared_grouped_table:
  keys[N, K], aggregates[N, A], valid[N]
  公开容量仍为 N；未使用的载荷清零；通过有效位区分合法零值
```

先支持一个键列、一个度量列，以及 COUNT(*) 和 SUM。
为多列保留形状约定，首个完整功能通过验证后再实现多列支持。
第一阶段不支持 SQL NULL、字符串、浮点数、DISTINCT、MEDIAN 或任意 SQL。
如果 JOIN 需要外连接的 NULL 语义，应扩展接口，增加逐列空值位；
行有效性与 SQL NULL 是不同概念。

COUNT(*) 统计有效的连接结果行，包括重复匹配，而不是去重后的人数。
SUM 包括负值和零值。集成适配器必须检查 MPC 协议、参与方顺序、计算域或环、
数据模式、编码和运行时或会话是否一致。
来自无关运行时的对象引用不能与秘密份额互换。
不得仅为连接不兼容的运行时而重构 JOIN 结果。

## 功能性排序基线（我们的提案）

1. 按 `(1-valid, key)` 进行不经意排序，将数值和有效位与整行一起重排。
   上游接口须保证有效位为比特值。无效行排在最后。
2. 秘密计算组边界。仅当当前行有效，且下一行无效或键不同时，才将当前行标记为组末尾；
   对最后一行显式处理。无效行不得产生任何返回的分组。
3. 对 `valid` 和 `valid * value` 计算整数分段前缀和，在每组起点重置。
   在支持的情况下使用并行扫描，并验证结合律和整数数据类型。
   COUNT/SUM 共用同一排序和边界计算阶段，批量完成计算。
4. 使用秘密条件选择，仅保留组末尾行；其他行的键和数值载荷全部清零。
5. 按 `(1-end, key)` 对组末尾行进行不经意压紧，使真实分组汇总按键顺序占据前部位置。
   输出长度保持 N，有效位向量继续保密。第二次排序是基线明确包含的成本，不能视作免费整理。
6. 返回秘密共享输出，不得将压紧前的组末尾位置或排序后的输入键以明文返回给调用方。

N=0 是公开形状的特殊情况，返回空数组。N>0 且所有行无效时，返回 N 个载荷清零的无效行。
合法的零键或零和仍然是有效结果。
该基线是基于分段扫描的改编方案，尚不声称其 COUNT/SUM 步骤复现了论文的置换与差分构造。

该基线优先采用确定性的安全压紧，而不是引入自行设计的洗牌。
最终授权公开结果时，压紧后的有效位会揭示输出分组数，但不会揭示各组原来的末尾位置。
如果连分组数也必须对接收方保密，则须在启用输出前制定另一种结果交付约定。
COUNT 本身就会公开组大小；仅请求 SUM 时，不得通过位置布局意外泄露组大小。

## 数值与信息公开约定

- 初期采用 int32 输入和累加器：声明公开容量 N 和数值绝对值上界 B，
  保证 N、N*B 以及中间累加值均可用有符号 int32 表示。
  在数据方输入阶段执行界限检查；这是半诚实输入下的假设，不是针对恶意输入的范围证明。
  使用任意精度 Python 整数参考实现测试。
- 如果更大的数据需要 int64，应先启用并验证 JAX x64 和 SPU 编译。
  仅选择 FM64 不会扩大 int32 JAX 运算的位宽。
  不接受静默的模溢出或退回浮点数计算。
- 公开元数据包括：填充容量、数据模式、查询列及聚合操作、数据类型、所选算法和运行时设置。
  功能测试无法证明不存在时间或资源使用方面的信息泄露。
  只有输入阶段也进行填充且不公开真实行数时，真实行数才会保持隐藏。
- 计算方将输入值、边界和中间分组计数保持为秘密共享状态。
  协调器只接收任务元数据和句柄，不接收明文表。
- 授权接收方只能获得最终键、请求的聚合值以及解释输出所需的有效位。
  接收方、分组数公开和结果保留规则仍为未决事项。目前尚未启用服务端结果交付。

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| 0：可行性 | 检查现有环境和内置原语行为 | 已完成两个合成数据冒烟检查，见调研记录 |
| 1：语义 | 实现类型与规格校验、Python 参考实现、有界测试数据 | 空输入、单行、全部同键、全部异键、负键和零键、零和、填充及数值边界均得到精确预期结果 |
| 2：MPC 基线 | 实现上述六个步骤和模拟器适配器 | 确定性测试数据及固定随机种子生成的数据与参考实现一致；检查编译输出中的秘密输入可见性、静态形状以及是否存在意外公开 |
| 3：复现 | 获取完整目标论文及版本；建立协议到代码的映射；实现所选 common/count/sum 构造 | 步骤、原语和假设映射完整，差异明确；与参考实现及基线结果一致；安全声明符合运行时能力 |
| 4：集成 | 商定 JOIN 接口；创建运行时适配器及共享的 JOIN 结构测试数据 | 算子之间不重构明文；支持全无效和含填充的 JOIN 输出；拒绝不兼容的运行时或数据模式 |
| 5：服务与演示 | 加入团队选定的任务 API 和授权结果交付适配器；运行独立工作节点 | 完成面向约定接收方的端到端合成数据演示；协调各方错误和取消处理；不记录私有中间结果 |
| 6：评估 | 比较公开候选键基线、排序基线和复现版本 | 可复现的正确性与性能报告，包括排序、聚合、压紧和结果交付成本 |
